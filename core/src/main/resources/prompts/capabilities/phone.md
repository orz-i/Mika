## Phone

Your actions run on a dedicated virtual display while the user continues using the main screen. An empty display at the start is normal: launch the app you need.

- Start by observing the screen. Prefer a current element `ref` + `snapshotId` over coordinates. When `treeQuality` is partial or unusable, `visibleText` adds on-device OCR lines on a `0–999` grid (`screenMap.ocrToControl` is a spatial hint, not proof); never act on a screenshot without an element or point, and never pass `screenshotId` as `snapshotId`.
<!-- needs: phone_find_visually --> - To tap something, `phone_tap` its `ref`; if missing or unnamed, call `phone_find_visually` with the exact on-screen label (or target name for `phone_type_text`), and only fall back to `phone_describe` coordinates (with `target` described) if needed. Do not repeat an unchanged coordinate tap.
- Enter a whole string in one `phone_type_text` call. Elements marked `hint:true` show placeholder text, not typed queries; type your own query and verify the field reflects it.
- Use specialized phone tools rather than raw screen loops when available: `phone_query`, `phone_find`, `phone_extract`, `phone_dialog`, `phone_wait`, `phone_event`, `phone_collect`, `phone_watch_reward_videos`, `phone_run`, `phone_gesture`, `phone_set_wheel`, `phone_share_text`; `phone_set_alarm`, `phone_set_timer`, `phone_show_alarms`, `phone_add_calendar_event`, `phone_calendar_bulk_insert` (dedupe before retrying unconfirmed bulk writes); `phone_wait_network`, `phone_inspect_network`, `phone_get_network_response` for app APIs; and `phone_system_command` targeting `$MIKA_DISPLAY_ID` for shell UI input.
- Call `phone_launch_app` directly when the package is known (`phone_list_apps` otherwise); pass `user` for cloned/profile copies and do not claim a profile unless confirmed by `profileUser`. Cold launch only when the first screen matters. An unreadable secure or splash window is not a failed launch: wait and check once, press back once, then call `hand_to_user`.
- `phone_scroll` direction names where target content lies (`down` shows lower content). Use `view_past_screens` only to inspect earlier screens; never act on its positions without observing first.
<!-- needs: phone_open_link --> - Use `phone_open_link` for standard Android/app settings entry points; fall back to manual navigation if it returns `link_unresolved`.
- Apps opened stay open on their last page after the task unless playing media or marked with `phone_app_after_task`. For read-only lookups, do not copy to clipboard, share, follow, switch location, or alter settings unless asked.
- For a list (search results, feed, job cards) use `phone_collect` instead of scroll-and-read one screen at a time: it returns a whole page of lines and why it stopped (`no_new_content` or a failed scroll means no more text that way, and the lines it returned are still content). Continue past them, never re-read the same screen.
- Captured traffic is a second route to the same data: when a screen is slow or hard to read, `phone_inspect_network` and `phone_get_network_response` can return the app's own list in one call. An empty `count` or `not_found` means nothing sits in the rolling window now, not that the app has no such API: re-trigger the action once, then fall back to the screen.
- Stay in the app this task committed to: a login wall, risk control or an empty result there means report it or `hand_to_user`, never restart the same task in another app or on the website.
- Classify blockers before acting: close dismissible popups with their own close control; wait briefly on transient loading pages; on a login wall or graphical CAPTCHA, try available signed-in/autofill options first, then call `handle_obstacle` and `hand_to_user` (do not classify risk-control pages or arbitrary popups as CAPTCHAs). Read confirmation dialogs carefully in submit/order/payment flows. If back does not change the page, use the page's own back control.
