# App 图谱治理：首批隐私与正确性修复

2026-11-19。范围是调研中已复现的六类问题及其存量数据处理，不扩展主动探索、UI 拓扑或新的自动执行能力。

## 已落地的约束

| 问题 | 修复 |
| --- | --- |
| 输入原文进入候选/快捷/分享 | 输入必须先按任务原话绑定成参数；不能绑定就切断该段。删除 `reason` 等临时参数，过滤输入回显；存储读取与写入均清洗历史输入，无法恢复参数的旧快捷/候选不再使用；回放前再次校验 |
| 同页不同输入框误合并 | 合并键包含输入框身份；缺少 resourceId 不再是通配符。无 id 时还须有序号与相邻位置证据；新增、历史合并和失败计数共用匹配口径 |
| 跨包点击变成启动入口 | 只有实际 `phone_launch_app`、请求包与观测落地包一致，才记录启动证据；外链仍可贡献页面访问，不生成虚假的启动边 |
| 精确目标被其他候选替代 | 仅保留最高匹配等级；同等级多候选返回歧义，要求明确 sigId，不按距离替用户选页 |
| 跳数预算下漏掉合法路线 | Dijkstra 距离与父边按 `(screenId, hops)` 保存，保留较贵但更短的前缀 |
| 分享摘要漏字段 | 分享格式 v2 对完整序列化内容作规范化摘要，覆盖权重、选择器定位字段、锚点、快捷状态与捆绑路线；步骤顺序不变 |

相关实现：`core/src/main/kotlin/com/wangzan101/mika/core/atlas/`，以及 `app/src/main/java/com/wangzan101/mika/atlas/FileAtlasStore.kt`。

## 旧数据与分享兼容性

- **不清空本机图谱**。读取旧加密文件时清理已知输入残留，保留页面、正常边与计数，原子加密回写。迁移写入失败不当作文件损坏，不隔离或覆盖原文件。
- 无法安全恢复参数的旧快捷和候选会被移除，不能再用于提示、执行或导出。输入原文也不能经临时动作说明继续进入新候选；学习时用本次输入在内存中剥离不可编辑标题/目标的回显。用户主动设置的页面名不因恰好与查询同名而覆盖，导出仍经过敏感信息过滤。
- `AtlasEdge.launchObserved` 默认 `false`。旧入口无法判断来自普通启动还是深链，必须通过一次新的本机启动观测重新获得执行资格，不能凭旧成功次数自动信任。
- 启动可能恢复最近任务；L3 启动后从**实际落地页**重新规划，不再沿预测首页继续点击。重规划消耗原有跳数预算，不会重新启动；无法识别落地页或没有预算内路径时停止。
- 分享格式为 **schema 2**。schema 1 的摘要漏掉执行字段，明确拒绝而非降级校验；需要从新版重新导出。本机存储格式不因此清空或重置。
- 导入保留图结构，但外部的边成功/失败次数不算本机执行证据，也不能提升已有本机边的计数。新导入快捷默认停用，需在现有管理页手动启用；已存在的本机快捷状态不被导入覆盖。这里不改变独立操作路线的导入启用策略。
- 内容摘要只能检测内容一致性，**不是数字签名或来源认证**。

# 2026-11-21：工具子步与页面能力

起因是看广告领奖那个整段工具（`docs/dev/reward-video-tool.md`）——它内部点「去完成」、点 CTA、
按返回，这些子步也会走到同一个执行入口，被记成 `ActionTarget`。

## 子步不是路，不能进图谱结构

`ActionTarget.source` 一直记着来源（`model | batch | script | replay | mcp_tool`），
组合工具的子步是 `Origin.Script`，`source == "script"`。学习器以前不看这个字段，
于是子步会被当成模型走的一步：建节点、建边、记控件。

现在 `AtlasLearner` 遇到 `source == "script"` 直接跳过结构部分。之前没出事纯属运气——
广告页本来就读不到无障碍节点，`afterSig` 是空白被丢掉；换一个有节点的广告素材，
图谱里就会长出 `福利中心 --phone_gesture--> 广告页` 这种一步一变的废料。

## 能力：这一页能整段干什么

新增 `AtlasScreen.capabilities`（最多 8 个）。只收工具名本身（例如 `phone_watch_reward_videos`），
不收调用参数、不收页面文字、不收用户原文。
子步事件带 `ActionTarget.parentTool`（发起它的工具名，由 `Origin.Script(parent = ...)` 一路带下来），
学习器拿它给**当前页**记一条能力：

- 只贴到认得出的页面上，认不出来就不贴，也不为它造节点——能力和边一样，不是造节点的理由；
- 只认 `effective == true` 的子步，失败的动作不算「这一页能干这件事」；
- 网页脚本的 `mika.*` 动作 `parentTool` 为 null，因此不会被误记成能力。

产物是提示词里的一行，排在边之后、控件之前：

```
- 可用工具 phone_watch_reward_videos：这一页能整段做完，不必一步步点
```

这行的价值在真机上很直接：模型见到这一页就不会自己拆成十几次 `phone_tap`（拆开一定卡在广告上）。

## 导入带不走能力

`sanitizeAtlasForImport` 里和边计数同一个口径：外部导入的 `capabilities` 一律清空，
页面与标题保留。别人机器上整段跑通，不等于这台机器上跑得通，不能凭导入就告诉模型「这页能干这件事」。

## 兼容性

`AtlasScreen.capabilities` 是有默认值的序列化字段，旧图谱文件解码得到空列表，本机存储不需要迁移；
分享格式仍是 schema 2（旧导出包里的摘要按它自己的内容算，仍能校验通过）。

## 验证

`AtlasCapabilityTest` 6 条：子步不进结构但记能力、陌生页不因能力造节点、无 `parentTool` 不记、
工具名校验与上限、提示里出现能力行、导入后能力为空。图谱包 84 条测试全部通过。


# 2026-11-22：回放不是证据

## 同一个漏洞的第二个口子

上一轮把整段工具的子步挡在图谱结构之外，过滤条件是 `source == "script"`。
但 `source` 还有另一个值：`replay`。回放、快捷流程（`phone_run_shortcut`）、
自动寻路（`phone_navigate_to`）都经同一个执行入口，产生的 `ActionTarget` 带着
`source == "replay"`；学习器那时只认 `script`，把它当模型自己走的一步。

后果比子步更隐蔽：**图谱在拿自己的旧结论给自己打分**。

- 一条边被回放十次，`ok` 涨十次，看着像「独立验证过十遍」；
- `learnDone` 时记的是强成功（`ok + 1`），于是一条只走过一次的路，越用越像铁律；
- 回放走到陌生页（走偏、A/B 实验、新弹层）会给它**新建节点**，把噪声当成发现；
- 控件 `used`、失败时的 `miss` 同样被回放刷高。

`RouteRecorder` 那条也有同一族的问题：整趟任务里夹着回放步骤时，它会把旧路线原样录一份；
更麻烦的是 `acts` 是「过滤掉不 routable 的步骤后拼接」，中间截掉一步就会拼出一条
**从没被执行过的流程**。

## 现在的口径：只有模型自己走的才算证据

三处过滤统一读 `Origin.SOURCE_MODEL / BATCH / SCRIPT / REPLAY`（新增的共享常量，
写事件与读事件不再各写各的字符串）：

| 消费方 | 处理 |
|---|---|
| `AtlasLearner` | `replay` 不进结构（不建节点、不建边、不记控件、不记失误、不记能力）；只给**已存在**的页面推后 `lastSeenMs` |
| `AtlasShortcutMiner` | `replay` 与 `script` 都 `flush()` 断开分段，既不参与挖掘，也不能把前后两步接起来 |
| `RouteRecorder` | 这一趟只要出现过 `replay` 或 `script`，整条不录 |

为什么 `AtlasLearner` 还要推 `lastSeenMs`：页面按 `lastSeenMs + hits` 混合评分淘汰。
长期靠回放跑的 App 里，如果回放完全不动图谱，页面会被 LRU 当成陈旧数据踢掉——
恰好把回放最依赖的东西删了。所以保留「这一页还在」这一条，`hits` 不涨：
它是「还在」，不是「又发现一次」。

为什么陌生页不建节点：回放只该走已经记下的路线。冒出陌生页说明走偏了，
那种页面学进去是噪声，不是发现。

为什么 `RouteRecorder` 是「整条不录」而不是「滤掉那几步」：拼接会产生从未执行过的流程，
比不记更糟。路线该由真正自己走出来的那一趟来定。

## 空图谱保护

`replay` 与子步能力都只能往已有页面上贴。没有既有图谱时写进去，除包名外空空如也，
还会占着「最近使用」列表。现在这类包直接跳过，不写记录。

## 验证

- `AtlasReplaySourceTest` 4 条：回放不建边、回放只推已存在页面的时间且不涨 `hits`、
  只有回放时不留下空图谱记录、连着回放同一条边十次 `ok` 原地不动；
- `AtlasShortcutMinerTest` 新增 2 条：整趟回放不晋升快捷流程、不抬高候选见次数；
  子步不拼候选也不拼快捷；
- `RouteRecorderTest` 新增 2 条：夹了回放步骤的运行不录路线、用了整段工具的运行不录路线；
- 图谱包 90 条、`RouteRecorderTest` 15 条全部通过。全量 `:core:test` 3465 条，
  唯一失败是本机 AdGuard 占 loopback 的 `HttpServerTest`（`windows-test-failures.md:215` 已记载），
  与本次改动无关。
